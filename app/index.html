                          Assistant

                          Off by default. When on, the assistant sends your questions and the board data it reads to the model server you choose below. The board data is headers, readings, and console and capture text. Photos go only if you allow them for a profile. Nothing is sent while the assistant is off, and the rest of the app works the same.

                          The assistant only suggests; you approve everything. See Settings and privacy.

                          A cloud profile needs an account and credit at OpenRouter. Create a key at openrouter.ai/keys. Paste it below. You pay per question, and the usage line under the Agent panel shows the cost. The suggested models read photos. Your questions and the board data they use go to that server. See Settings and privacy.

                          Get a key at openrouter.ai/keys. You pay per question. Set up the assistant

                          A local model runs on this computer and needs no key or account. Install Ollama with sudo pacman -S ollama. Start it with sudo systemctl enable --now ollama. Then download a small model, for example ollama pull llama3.2:3b. Use the address http://localhost:11434/v1 and that model name. To read photos, use a vision model. A small text model cannot read photos.

                          Ollama: sudo pacman -S ollama, ollama pull llama3.2:3b, address http://localhost:11434/v1. Set up the assistant

                          A model server on another machine, such as Ollama on a home server, must be reached through an SSH tunnel, because only https:// addresses are allowed off this computer. In a terminal, run ssh -N -L 11434:localhost:11434 <host> and leave it open, then use the address http://localhost:11434/v1.

                          Another machine: ssh -N -L 11434:localhost:11434 <host>, address http://localhost:11434/v1.

                          Name it for what it is to you, for example Cheap and Expensive, or Fast and Careful. Both cloud slots work the same way.

                          Deep lets the assistant look at more of the board before it answers. On a paid server one question can cost several times as much; the usage line shows what it cost.

                          Prices are in dollars per million tokens.

                          Test sends one short question to the saved settings of this profile. The question is "Reply with the word ok." It sends no board data. Test also checks that the model can use the assistant's tools. It may cost a fraction of a cent. If you changed something, save first.

                          Git

                          Off by default. Boards are plain folders either way. When on, the data folder is a git repository with a commit guard that scans for secrets, and pcbv sync commits changes. Nothing leaves this computer unless you set a remote address; then sync pushes the commits there.

                          Work through the steps in order; each shows its result before the next. Git turns on only when the local checks pass. See Settings and privacy.

                          1. git and gitleaks are installed

                          2. repository, commit guard, ignore rules

                          3. they carry location data and stay out of git

                          4. To back up to GitHub, first create a new, empty, private repository at github.com/new. Leave "Add a README file" off. A public repository would publish every board, capture and note.

                            Then log in, one of two ways. Recommended, the GitHub CLI: run sudo pacman -S github-cli, then gh auth login. Choose GitHub.com, HTTPS, "Login with a web browser", and answer yes to "Authenticate Git with your GitHub credentials". Use the address https://github.com/<owner>/<repo>.git.

                            Or use an SSH key. Run ssh-keygen -t ed25519. Add the public key on GitHub. Check it with ssh -T git@github.com. Use the address git@github.com:<owner>/<repo>.git. The steps are on the Back up to GitHub page.

                            Create an empty private repository at github.com/new. Then log in with gh auth login or an SSH key. Back up to GitHub

                            For a github.com address this step asks GitHub whether the repository is public, without logging in, and refuses a public one. Then it checks that git can read the repository.
